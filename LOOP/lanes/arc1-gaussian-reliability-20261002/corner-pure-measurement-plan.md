# Recommended reduction to pure fixed-coordinate measurement

Judgment: sound and preferable. The next unanswered question is whether physical corner derivatives and scores behave as expected at four saved coordinates. Measuring those quantities does not require duplicating production eligibility, complete-history collection, shared-point acceptance, or an optimizer state machine. Those requirements remain mandatory before any new method can accept a profile. This measurement cannot establish local feasibility, certify a candidate, change a raw status, close a gate, or select a new method.

The four saved native records already identify the proposed corner. Use one explicitly pinned terminal candidate for each point; do not select a new winner based on measured values. Preserve the existing profile refusal and all original artifacts. A missing or failed measurement remains a raw missing/error result. Successful script completion means only that observations were saved.

## Minimal measurement contract

The script should be roughly 30 to 80 lines of direct evaluation and persistence. Keep source/runtime/artifact/argv pins, timeout, before/after hashing, exact four-point coordinates and module-path checks in the reviewed wrapper. Do not rebuild those controls inside a second framework.

1. Explicit imports: Serialization, LinearAlgebra and HSquared. No helpers borrowed implicitly from unexported modules. Exact Julia 1.10.0, one thread and BLAS one are enforced by the wrapper and checked at launch.
2. Accept the two pinned inputs/profiles and one empty output directory. Deserialize them, obtain the four exact saved rows and preselected native terminals, and retain case, Ve, candidate index and source artifact hashes in the output.
3. Build each input's existing covariance context once, outside its two-witness loop. Use saved s0 and residual df. No optimizer, point fit, profile search, newly chosen start, or parameter update is called.
4. At each fixed Ve, measure the chosen saved tiny-positive terminal and `[0,0,Ve]`. Independently repeat the direct corner likelihood evaluation as the intersection comparison. Also retain the saved independently certified corner score and coordinates as original data, clearly distinguished from recomputed values.
5. For each measurement append a raw entry and immediately persist it. Call the direct full evaluator first, save its return/error, then call the analytic gradient evaluator, save its return/error, then the fixed-Ve centered evaluator and save its return/error. Preserve any earlier valid value when a later call throws. Retain all fields returned by these evaluators and explicit component coordinates, not a fabricated success boolean.
6. Measure the 12 nonzero probe coordinates: s0*h*d and s0*2h*d for d=(1,0),(0,1),(1/2,1/2), h=1e-4 and 1e-5, holding Ve fixed. Record both full and centered scores. Derivative calls at nonzero probes are optional and should not be added unless their results answer a stated question; the corner's analytic gradient supplies g dot d.
7. Store s0*dq/da and s0*dq/dp at the corner, where q=-ell/df. For each direction store both forward estimates, their differences from g dot d, and their mutual difference. Compute these from raw full and centered score variants separately, with scale labels. If any operand is missing/nonfinite, retain missing arithmetic and the raw error, not a fallback value.
8. Store terminal/corner/repeated-intersection/saved-corner score spreads separately for full and same-Ve centered scales. These are measurements, not pass/fail tests. Do not compare them with acceptance thresholds in the executable or emit `feasible`, `certified`, `history_complete`, `accepted`, or equivalent fields.
9. A per-witness try/finally writes all accumulated raw entries and exception information even if later arithmetic or access fails. Checkpoint after each evaluator return or caught exception so a timeout preserves earlier observations. Keep first-witness output if the second fails. An interruption is recorded and rethrown for wrapper cleanup.
10. Return only an observation-completion record listing measured/missing operations and output hashes. The wrapper separately reports process exit, timeout, child cleanup and unchanged pins. Completion is not scientific acceptance.

Estimate: 20 to 45 seconds for this one measurement on the local host, with a 60-second process-group cap. No execution has occurred under this proposal. Review the short exact script and wrapper before launch. A tiny fake-function test should cover full-result retention when the next evaluator throws, and a failing second witness after a saved first. A metadata-only dry entrypoint check should confirm the actual imports, native fields and coordinates before real evaluation.

## Interpretation after measurement

An independent scientific read can compare the observed derivatives, forward differences and spreads with the unchanged proposed conditions. Passing arithmetic would justify drafting an explicit versioned corner-certificate method and its production tests. It would not establish complete-history safety or population reliability. Failed arithmetic directs the next diagnosis, with failures retained. Production must still prove native eligibility, fixed components, shared budget, no new optimization/chaining, both active physical directions plus joint numerical checks, all retained full and correctly tagged centered histories, unrestricted-point and unrelated-competitor guards, exact winner consistency, and unchanged v1/v2 meanings. No tolerance, model, allocation or criterion changes follow from this reduced measurement.
