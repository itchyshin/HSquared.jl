## Julia full package suite

The fixed command runs Julia with the repository project and Pkg.test(allow_reresolve=false), one Julia/BLAS thread, one precompile task, and offline package behavior. The installed Julia 1.10 Pkg source supports allow_reresolve=false. Do not run before the source freeze and runtime pins are independently reviewed.

Pass requires exit zero, the package test-suite terminator, parseable Julia Test Summary tables, zero Fail, Error, and Broken counts in every parsed summary, and passing top-level Arc1 summaries for objectives, optimizer contracts, profiles, bootstrap, interfaces, independent DGP, provenance, executor, and reference admission. The five-target profile wrapper is nested under the profile testset, so Julia does not emit a separate nested summary; the runner forces ARC1_SKIP_EXPENSIVE_PROFILE_WRAPPER=0 and checks that the frozen test source contains the expected enabled branch and wrapper. Its assertions therefore contribute to the passing profile summary. Broken is Julia Test’s skipped/broken count. The runner retains each summary row rather than summing nested testsets, whose totals may overlap. Missing summaries, a zero-assertion required top-level set, a nonzero failure/error/broken count, a missing Arc1 label, timeout, interruption, missing fixture, or changed frozen input fails the component. It does not prove Arc1 calibration or any scientific gate.

## R package check

The runner first executes the isolated package’s mandatory Arc1 live testthat driver with the current Julia project, the expensive wrapper skip disabled, and Arc1-required mode enabled. The driver requires the four Arc1 test files and rejects empty results, failures, errors, or skips. It then runs devtools::check(document=FALSE, cran=FALSE, error_on="never") into the unique evidence directory. The check driver retains the R CMD check log and writes machine-readable JSON counts for errors, warnings, notes, and exact Status: OK status; pass does not depend on dput formatting.

Pass requires both processes to exit zero, the live-driver and package-check markers, nonempty live RDS/CSV results, exactly zero errors/warnings/notes, and a check-log line exactly equal to Status: OK. Historical R receipts are feasibility references only, not current-source evidence. The diagnostic Quarto version probe may appear in the output; it does not change the explicit R CMD check result. The full check tree, live artifacts, raw logs, and JSON result are hashed in the run receipt.

## Local documentation build without deployment

Do not invoke docs/make.jl directly: it resolves the package, writes the source validation page, emits a redirect in the build tree, and ends with a VitePress deploy call. The runner copies docs/Project.toml and docs/Manifest.toml into the unique evidence run and rebases only the HSquared local path in both copies to the frozen Julia root. All other project and manifest bytes remain identical. It does not run Pkg.develop, Pkg.instantiate, resolve dependencies, or edit repository manifests.

The runner copies docs/src to scratch and transforms the frozen make script with count-checked edits. It preserves the page list, makedocs options, warning policy, and VitePress format. The validation-table writer targets only the scratch page; Documenter receives scratch root/source/build paths; the legacy redirect helper writes only to that scratch tree. The transformed script asserts that pathof(HSquared) resolves to the frozen root’s src/HSquared.jl before generating the status table or pages. Julia runs under the copied docs environment. The runner confirms docs/src/validation-status.md, any existing docs/build, and scratch Project/Manifest hashes remain unchanged. It retains the transformed script, generated validation page, output-tree hash, rendered validation-status HTML hash, and redirect checks.

Pass requires exit zero, the docs component marker, the source-path assertion, generated-table markers, Documenter output with bases.txt, and the expected legacy redirect and validation-status page. Missing-documentation warnings remain visible in the raw log and are not described as an error-free build. This command has no deployment or push operation.
