## Automatic rank is a separate usability gate

The fixed `K=1` FA and `K=2` Poisson GLLVM cells above are reproducible
acceptance targets. Eventual users should not have to supply a rank if an
automatic choice proves reliable for this genetic model.
Shinichi's 2026-09-27 auto-d decision for `gllvmTMB` and `GLLVModels.jl`
(`shinichi-brain/memory/DECISIONS.md`, D-293) uses a guarded candidate-rank
sweep with BIC based on the number of sites as its first rule. Its results do
not validate automatic rank selection for HSquared's pedigree genetic models:
the integration objective, random-effect covariance, identifiability limits,
and effective sample size need their own check. Keep the current fixed-rank
cells available as cross-checks; consider an opt-in automatic-rank follow-on
only after candidate failures and rank recovery are reported.

The available ASReml-R documentation specifies `fa(obj, k)` with an explicit
factor count, `fa.init()` for initial parameter values, and automatic loading
constraints/rotation during a chosen-rank fit. It does not document a built-in
rule choosing `k`. Szymek may be using a wrapper or a newer feature; obtain
the exact command/version before treating that as comparator behaviour.
Sources: [ASReml model functions](https://asreml.kb.vsni.co.uk/knowledge-base/asreml/),
[FA starts](https://asreml.kb.vsni.co.uk/knowledge-base/fa-init/), and
[FA options](https://asreml.kb.vsni.co.uk/knowledge-base/asreml-options/).
