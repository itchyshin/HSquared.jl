## Deviations from the original route

1. The original generic H1 smoke was replaced by an identified H1-two fixture.
   That replacement generated retained evidence, but the frozen interpretation
   is directional-conservative and specific to its DGM.
2. H3 did not advance from smoke to campaign.  The first actual sealed smoke
   produced zero intervals, so any S11 estimate or array would have lacked a
   valid acceptance basis.
3. The Totoro launcher required a source-inert correction to call its explicit
   Julia binary.  The pre-fix receipt is retained as a zero-fit technical
   failure; it is not used as H3 numerical evidence.
4. R candidate integration has not been folded into `origin/main`; this is
   deliberate because no release-science gate authorizes it yet.

## What remains decisional rather than implementable

- **H3:** ratify a replacement identified protocol, or explicitly remove any H3
  interval claim from 0.9.0.  The governing choice is
  `docs/dev-log/decisions/2026-09-09-h3-s10-no-go-decision-card.md`.
- **Release scope:** decide whether 0.9.0 remains contingent on H0/H3, then
  reconcile that decision across both twins before candidate integration.

## Explicit deferrals preserved

0.10 scope, extra families, production sparse kernels, FA R activation,
default single-step/genomic activation, Grok retrieval, and the broad 0.9.x
adversarial campaign remain outside this release programme.

## Negative space

This reconciliation does **not** cover a new H3 fixture, H0 computation,
calibration, R-public promotion, release CI, external-comparator expansion,
versioning, tags, registry actions, publication, or post-release DRM-style
hardening.  It makes those unpaid items visible rather than treating any one
passing local check as a release proxy.
