## Known deviations, verified against source

Each item below was checked against a report file, the gates ledger, or a live `gh` call rather
than accepted as given; three carried a correction.

**(a) Agent-type relaunch.** Confirmed by the checkpoint's own text ("j2 (#327) and j4
(#214/#217 engine) were relaunched as `general-purpose` after the gauss/karpinski agent types
declined to implement"); no report file documents the refusal itself (the surviving reports are
from the successful `general-purpose` run), so this rests on the checkpoint as the durable
record rather than a first-hand repair-agent artifact. Accurate as stated.

**(b) Rose needed three rounds per twin.** Confirmed directly from the report set: Julia —
`rose-julia-a.md` (3 PRs, one BLOCK on `#339`), `rose-julia-b.md` (`#341`/`#342` reviewed for the
first time, `#337` re-approved, `#339`/`#342` sent back for a second repair), `rose-julia-c.md`
(`#339`, `#338`, `#342` re-audited). R — `rose-r-a.md` (all four builder PRs, CHANGES on each),
`rose-r-b.md` (`#226`), `rose-r-c.md` (`#227`). Accurate as stated: two repair rounds per Julia
PR that needed one (`#339`, `#342`, `#338`), versus the plan's assumption of one round.

**(c) `#339`'s BLOCK and its resolution.** Confirmed from `rose-julia-a.md` §"#339 — BLOCK": the
df fix (correctly subtracting the rotation-group dimension) routed the `t=5, K=2` FA headline
case into `nested_lrt`'s single-boundary 50:50 chi-bar branch, while the PR's own docstring and
runtime `note` string claimed the returned p-value was the "naive χ²`df`" one whose direction is
unknowable without mixture weights "which this function does not compute" — a direct
contradiction on the case the new test exercised. Rose named two defensible resolutions and
declined to pick between them (a statistical-correctness call, not a wording one); the accepted
fix ("resolution 1": code matches the docstring's naive-χ² claim, i.e. take the plain χ²`df` tail
for structured/non-convex nulls rather than the chi-bar mixture) changes the returned p-value on
the low-rank `t=2, rank=1, df=1` case to double its pre-fix value, and Rose's round-C audit
(`rose-julia-c.md` §"F1 is resolved") is what confirmed the code now matches the docstring and
that the number changed — the round-A audit that found the BLOCK did not yet know which
resolution would be chosen. Accurate as stated.

**(d) R1 and R3 started against unmerged Julia branches.** R1 is unambiguous: `r1-212.md`'s own
header states "Julia half: HSquared.jl PR #337 (`claude/h2-fixer-j3`, **not yet merged**), tested
live against [the j3 worktree]." R3 is weaker evidence than the brief implied: `r3-214-217.md`
states the J4 dependency in future tense ("[PR #341] must merge before this PR") and the report's
write-timestamp sits within about a minute of `#341`'s actual merge, which is consistent with (but
does not prove) dispatch before the merge landed. Recorded as ADAPTED for R1 on direct evidence,
and as a probable-but-weaker instance for R3.

**(e) The `#220`×`#223` cross-PR hazard.** Confirmed: `rose-r-a.md`'s merge-tree review (not CI)
found that `#220`'s `hs_engine_control_honoured_keys` change would silently drop `max_dense_cells`
support that `#223` needed on `fit_animal_model`/`repeatability`, with CI on each branch alone
staying green throughout. `merge-223.md` documents the per-function resolution and the
re-verified cross-PR regression test surviving the final `main`-merge. Accurate as stated.

**(f) Added slices.** Confirmed above (R6, diag-boundary, merge-223, jrec/rrec, repair agents),
with the repair-agent count corrected from 9 to 10.

**(g) Added issues.** Confirmed live via `gh issue list`: `HSquared.jl` — `#340` (ngen follow-on,
pre-authorised by the plan itself, not a surprise), `#343`, `#344`, `#345` (all `OPEN`, all
follow-on to a fixer PR). `hsquared` — `#222` (`OPEN`, follow-on to `HSquared.jl#327`), `#224`
(`CLOSED`, fixed by PR `#226`), `#225` (`OPEN`, the non-Gaussian-`initial` gap `diag-boundary`
flagged but did not require fixing). All present as stated.

**(h) NEWS discipline.** Corrected: the brief said "R2/R4" wrote NEWS despite the "R5
consolidates" rule. `rose-r-a.md`'s own diff count (`git diff origin/main -- NEWS.md`) shows
**three** PRs violated it, not two: "r2 +11, r3 +22, r4 +77; r1 empty." R3, not just R2 and R4,
added a NEWS hunk that Rose ordered removed (`R3-1`). R1 (`#223`) is the one PR of the four that
left NEWS untouched.

**(i) G4's CHECK formula.** Confirmed via `merge-223.md`: a live-suite run that summed only
`failed` read `FAIL=0` and would have silently passed, while a second summation that also
counted the `error` column found `ERROR=6` (one pre-existing `hsquared#224`, five boundary
refusals later diagnosed by `diag-boundary` and fixed by R6). The gates ledger's G4 CHECK line
now reads `sum(r$failed) + sum(r$error)`, matching the corrected method. Accurate as stated, and
recorded in the checkpoint as an explicit LESSON.

**(j) Transient Documenter gh-pages race.** Confirmed via the checkpoint and `rrec.md`/jrec's own
check-log note: the Documenter run at `#337`'s merge commit failed only at the `git push … HEAD:gh-pages`
step (a non-fast-forward race against a concurrent gh-pages write, not a build error); the very
next Documenter run, at `#341`'s merge commit, succeeded, confirming the race was transient
infrastructure. Accurate as stated.

**(k) `main` merged into branches, never rebased.** Confirmed via `merge-223.md`'s own statement:
"No rebase, no force-push, no `git reset --hard` / `git checkout -- <file>` used anywhere in this
resolution." Accurate as stated.

**(l) V1.** Not yet run at writing time — see the V1 row above. Labeled UNMEASURED.

**(m) Wall-clock and concurrency.** The first Julia PR (`#337`) was opened `2026-09-13T17:32:43Z`,
consistent with the checkpoint's own "~11:15 local" dispatch note under a UTC−6 (Mountain
Daylight) offset (17:32 UTC ≈ 11:32 local). The last merge of the campaign, `hsquared#227`, landed
at `2026-09-13T21:25:16Z` ≈ 15:25 local. **Wall-clock actual ≈ 4 h 10 min**, against the plan's
≈ 6 h estimate — the campaign ran faster than planned, not slower, and did not span a session
boundary as the plan's context-brake note worried it might. The ≤5-live-children cap is
confirmed for the Julia checkpoint's own opening dispatch ("five builders dispatched … (5 live)"),
but I cannot confirm from the sources available to me that concurrency stayed at or under 5 through
every later phase (repair rounds, diag-boundary, merge-223 running alongside R-lane builders) — no
process-level concurrency log exists to check against. Labeled UNMEASURED for the sustained cap,
though no source records or implies a breach.
