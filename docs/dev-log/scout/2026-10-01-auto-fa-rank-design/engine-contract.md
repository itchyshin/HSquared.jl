## Exact engine route

`fit_multivariate_reml(Y, X, Z, Ainv; genetic_structure, rank)` is a dense Gaussian REML fitter. It takes one shared record-level `X`, expands it trait-wise, and uses the same `Z` and pedigree relationship `A` for every candidate. Missing trait records are accepted by the general engine but are outside the proposed automatic-selector cell. The model has marginal covariance `Z_full (A ⊗ G0) Z_full' + R`, where `R` is block-diagonal over individuals from the common trait-level `R0` [src/multivariate.jl:917-948, 797-828].

The K=0 diagonal comparator is already a distinct supported route: `genetic_structure=:diagonal`, with `rank` omitted. The public fixed-rank diagonal route uses `G0=diag(exp(θ))`, with no uniqueness floor, has `T` free genetic variances, and returns `genetic_rank=nothing`, `genetic_loadings=nothing`, and `genetic_uniqueness=diag(G0)` [src/multivariate.jl:693-723, 1041-1050, 1174-1190]. This is a diagonal genetic covariance with positive trait-specific genetic variance, not a no-genetic-signal model.

The K=1 candidate uses `genetic_structure=:factor_analytic, rank=1`; the current validator accepts only integer ranks `1:T`, and the constructor also requires at least one loading column. FA uniqueness is `ψ=1e-4+exp(θ)` while public diagonal variances are `exp(θ)` with no floor [src/multivariate.jl:409-417, 463-472, 693-723]. Do not route K=0 through the FA helpers or relax those guards. A selector that claims diagonal K=0 is nested in FA K=1 must internally floor-match its diagonal variances, while leaving the public fixed-rank diagonal route unchanged. This adaptation is owed implementation work; directly relabeling current public `:diagonal` and FA `rank=1` fits does not preserve exact nesting. K=1 FA can approach the floor-matched diagonal submodel as common loadings go to zero, but loading directions are unidentified at that boundary. The no-genetic-signal boundary is a separate future witness because neither positive-variance diagonal comparator includes zero trait variance.

For a common `T=4` cell, generic covariance dimensions after rotational redundancy are `q_G(K)=TK-K(K-1)/2+T`: K=0 diagonal has 4; K=1 FA has 8; K=2 has 11. The current FA optimizer coordinates for K=1 are 4 loading values plus 4 uniqueness values; residual `R0` contributes `T(T+1)/2=10` parameters in both candidates. Thus the floor-matched K=0 selector candidate has 14 covariance parameters and K=1 has 18 under this generic count; the fixed intercept coefficients are common to both models, with four fixed coefficients for an intercept-only four-trait design [src/multivariate.jl:660-671, 693-723, 1041-1055]. The T=4 K=2 count exceeds the ambient 10-dimensional genetic covariance and is excluded in the current plan; the count screen is not an identification proof [docs/design/auto-fa-rank-design-plan-20261001.md, Symbolic alignment required first].

## Objective and criterion boundary

There is no `method=:ML` argument in this fitter: it optimizes the full-constant Gaussian REML objective only. Its log-likelihood includes `(N-p')log(2π)`, and the implementation explicitly says comparisons require matched data and compatible fixed-effect spaces [src/multivariate.jl:844-856, 917-934, 1010-1021]. Both genetic structures append the same `T(T+1)/2` log-Cholesky residual covariance coordinates and use the same `_mv_reml_loglik_core`, so they can be evaluated under the same REML objective at identical `Y, X, Z, Ainv`; nesting still requires the selector-only floor-matched diagonal parameterization above. This does not settle whether REML information criteria are defensible for rank choice, what sample-size convention BIC should use for multivariate repeated records, or whether an ML objective should be added for selection. Those are open C0 method decisions in the design plan, not current engine capabilities [docs/design/auto-fa-rank-design-plan-20261001.md, ticket C0].

If future design selects ML, it needs an explicit marginal ML objective with fixed effects profiled or jointly optimized under a declared convention, and both candidates must use it. Do not label the current REML output ML. Fixed-effect dimension treatment, constants, effective sample size, and the nominal parameter counts need to be stated together for any information criterion. The existing scalar covariance-structure LRT uses nominal generic counts but flags rank/PSD boundaries and does not justify ordinary likelihood-ratio regularity for this diagonal-to-FA comparison [docs/design/validation-debt-register.md:79].

## Starts, failures, and diagnostics already available

For FA with no user `initial`, the fitter attempts two starts, `:default` and `:balanced`; a supplied initial object produces one `:user` start. Each attempt records finite/admissible status, optimizer convergence, iterations, and objective. Selection filters to valid finite attempts, prefers converged attempts if any exist, then picks the highest likelihood; if none are valid it throws instead of returning an all-failed result [src/multivariate.jl:761-768, 1097-1135].

FA diagnostics expose strategy, attempted starts, selected start, objective range, relative G/R disagreement, a better valid nonconverged-start flag, minimum uniqueness, distance to the absolute `1e-4` uniqueness floor, near-floor flag, and per-start loglik/valid/converged/iterations/floor details [src/multivariate.jl:409-417, 1137-1167]. These are optimizer-start diagnostics for one fitted rank. They do not provide a cross-rank attempt table, an eligibility rule for rank selection, retry budget, criterion differences, a boundary/no-signal flag for the diagonal candidate, or rank-selection uncertainty. Convergence and positive Ledermann slack are not identification checks [src/multivariate.jl:419-460; docs/design/auto-fa-rank-design-plan-20261001.md, Required acceptance content].

## Payload and oracle inventory

The Julia fit result contains covariances, correlations, heritability, beta, breeding values, genetic structure/rank, loadings, uniqueness, loglik, convergence, iterations, FA start diagnostics, and trait labels [src/multivariate.jl:1174-1191]. The general bridge payload deliberately allows only rotation-free `:diagonal` and `:unstructured` structures; it rejects FA/low-rank loadings. A separate structured payload exists for fitted FA summaries but marks uniqueness identification as not assessed. Therefore an automatic selector result cannot simply be represented by the current general payload: a new selection-level object/payload must retain the complete attempt table and rank criteria without implying loadings or uniqueness are identified [src/multivariate.jl:172-205, 220-270; docs/design/validation-debt-register.md:80].

Available independent checks include `_multivariate_reml_loglik` for reevaluating a returned covariance pair on the exact input design, a fixed-evaluation oracle in the FA unit/order recovery harness that checks loglik, beta, and EBVs, and a separate base-R dense REML/BFGS same-model reference for one T=4/K=1 pedigree fixture. The latter matched objective and fitted outputs but used a truth-based start and approached the uniqueness floor; it is not an external package comparator or a multi-start/global-optimum proof [src/multivariate.jl:907-915; docs/dev-log/recovery-checkpoints/fa-unit-order-20260930/fa_ordinary_unit_order_check.jl:128-175; docs/dev-log/recovery-checkpoints/fa-same-model-exact-20260930/fa_same_model_reference.jl:6-32; docs/dev-log/scout/2026-09-27-fa-same-model-reference.md, Exact-current-source rerun].

The existing exact FA unit/order harness exercises complete T=4/K=1 pedigree fits, trait permutation and unit maps, ordinary default plus balanced starts, output ordering, covariance reconstruction, floor fields, and independent fixed-covariance likelihood/EBV reevaluation. It is useful validation scaffolding, not an automatic-rank test [docs/dev-log/recovery-checkpoints/fa-unit-order-20260930/fa_ordinary_unit_order_check.jl:315-355]. The earlier structured recovery protocol had 8/10 FA cases pass and remains a separate broader-cell limitation; current T=4/K=1 engine evidence is bounded and does not establish general FA calibration or automatic selection [docs/design/validation-debt-register.md:79, 115].

## Relevant limits for the proposed design

- Current rank-one FA has an absolute genetic uniqueness floor of `1e-4`; it is not equivariant to trait rescaling near the bound. Keep the floor distance visible for every candidate and treat floor proximity as a flag, not proof of a rank [src/multivariate.jl:409-417, 1137-1165].
- The Ledermann screen gives T=4/K=1 slack 4, while K=2 has negative slack under the formula. This is a dimension screen only. The T=4/K=0 diagonal model has no factor rotations and should use its own parameter count [src/multivariate.jl:419-460].
- The capability ledger's covered V4-FA row records legacy constructor/helper and engine-reduction evidence, including a bounded T=4/K=1 engine cell. It does not itself establish automatic-rank selection. Keep that historical covered evidence separate from the current fixed-rank opt-in fitted route and its newer experimental receipts. Remaining debt includes broader FA, external comparator parity (including WOMBAT), interval calibration, and expanded R exposure; `public_covered_count` remains 7 [docs/design/validation-debt-register.md:79, 115; docs/design/capability-status.md:13, 48; docs/dev-log/scout/2026-09-27-fa-same-model-reference.md].

## Readiness implication

The implementation route can remain narrow: retain the current fixed-rank fitter and public diagonal route unchanged, add selector-internal floor-matched K=0 and reuse the existing FA K=1 and shared residual objective, then make criterion/failure/table decisions before implementation. The floor-matching adaptation is required for exact nesting and is not present today. The unresolved method decision is whether the selector compares matched REML objectives with a justified criterion or requires a new ML objective. Existing tests, objective reevaluation, ordinary FA start diagnostics, and independent reference code provide useful components, but none validates automatic rank selection or its criterion.
