## Findings and required regressions

### E4-01: medium, PSD tolerance accepts a substantively indefinite tiny G

At baseline, `_check_symmetric_psd_G` described scale-relative tolerances, but used `max(1.0, maximum(abs, G))` and `max(1.0, maximum(abs, eigenvalues))` (`src/evolvability.jl:35–47`). For G well below one, the absolute floor dominated. A no-fit probe, `G = [1e-12 0; 0 -1e-12]`, returned `evolvability(G, [0,1]) == 0.0` and `genetic_pca(G).values == [1e-12, -1e-12]` instead of rejecting a matrix whose negative eigenvalue equals its entire positive scale. This undermined the stated PSD-safe metric and plot-data contract (`74–87, 167–187, 224–246`). The coordinator's candidate replaces the unit floor with matrix-scale tolerances, adds a nonempty guard, and checks PSD again after normalizing each positive-variance trait (`src/evolvability.jl:35–64`). The latter check rejects the additional unequal-units indefinite matrix `[1e-20 1; 1 1e10]`, whose global-scale eigenvalue tolerance alone was too permissive. The coordinator reports a final focused 23/23 run in `test/wave4_covariance_contracts.jl`, now included at `test/runtests.jl:11059`; this reviewer did not independently run it.

### E4-02: medium, genetic-correlation plot data can exceed its promised range

`genetic_correlation_plot_data` delegates directly to `genetic_correlation(G)` and promises off-diagonals in `[-1,1]` (`src/evolvability.jl:249–267`). At baseline, the delegated check in `src/multivariate.jl:20–37` used an absolute `eigmin >= -1e-8`. A no-fit probe, `G = [1e-12 2e-12; 2e-12 1e-12]`, returned `genetic_correlations = [1 2; 2 1]`; this G has a negative eigenvalue of `-1e-12`. The coordinator's candidate applies a matrix-scale PSD guard and checks the scaled correlation before clipping negligible roundoff (`src/multivariate.jl:20–46`). The normalized check also catches the unequal-units matrix above: its correlation would be far outside `[-1,1]` despite a tiny negative eigenvalue relative to the largest covariance entry. R's multivariate plot-data path can consume this preparer (`R/julia-bridge.R:5609–5653` in the bounded R worktree), but this input was not run through R.
